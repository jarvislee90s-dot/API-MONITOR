从零重建（换电脑 / 删除后重来时才需要）

1部署反代 Worker（命令行，1 分钟）

前置：.env 里已有 CLOUDFLARE_API_TOKEN（需有 Workers Scripts 上传与 Zone DNS 编辑权限）。

# PowerShell，在项目根目录
cd E:\LLMproject\ApiMonitor
$env:CLOUDFLARE_API_TOKEN="你的token值"
npx wrangler deploy --config supabase-proxy/wrangler.toml

成功标志（最后几行）：

Uploaded supabase-proxy
Deployed supabase-proxy triggers
  supabase.bondtoolbox.asia (custom domain)  ← 出现这行说明域名也绑好了

若只部署成功、没有 custom domain 那一行 → token 缺 DNS 权限，走下面的步骤 2 手动绑。

2（仅当没绑上域名时）控制台手动绑域名

带图参考：Cloudflare 官方文档 · Custom Domains（含界面截图）

dash.cloudflare.com 登录▶ 左侧菜单 Workers & Pages▶ 点列表中的 supabase-proxy▶ 顶部 Settings 标签▶ Domains & Routes 卡片 → Add▶ Custom domain▶ 输入 supabase.bondtoolbox.asia▶ Add domain

等状态从 Initializing 变成 Active（1~2 分钟），DNS 记录自动创建，不用去 DNS 页面手填。

另一个项目怎么复用

反代已支持多项目映射（按入口域名转发到不同上游项目）：

入口域名上游 Supabase 项目服务的项目
supabase.bondtoolbox.asiacdzjuvewreribelvpccz.supabase.coApiMonitor 看板
supabase2.bondtoolbox.asiaonexoaebobgpwokgoxwy.supabase.coBond_Toolbox
  • 接入方式：把项目的 Supabase 地址换成对应入口域名（env 里的 SUPABASE_URL、前端 createClient(url, key)、VITE_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_URL 等），密钥保持不变。
  • 接第三个项目：改 supabase-proxy/wrangler.toml 两处——UPSTREAM_MAP 加一条、[[routes]] 加一个新入口域名，重新 npx wrangler deploy。
  • Edge Functions（跑在 Supabase 服务器上的 functions/）服务端到服务端不受影响，不用改。
  • 安全边界：反代只换"门牌号"，数据访问仍需 apikey/Authorization（密钥不经过反代）；转发目的地固定为映射表内的项目，别人不能拿它当跳板。

常见问题

Q1：为什么首次请求偶尔要几秒钟？

Cloudflare Worker 冷启动 + 首次 TLS 握手，属正常。部署后第一次访问曾 30+ 秒，之后稳定在 4 秒左右（该接口本身要实时拉取全部 provider）。

Q2：为什么不直接用 xxx.workers.dev？

*.workers.dev 在境内被 DNS 污染/Sinkhole（Cloudflare 社区确认），必须绑自有域名。

Q3：Supabase 控制台打不开了怎么办？

控制台只是配置时偶尔用一次，挂代理打开即可；日常数据访问走 supabase.bondtoolbox.asia 完全不受影响。

Q4：怎么看反代的流量/报错？

Workers & Pages → supabase-proxy → Metrics（指标）/ Logs（实时日志）；/healthz 可随时探活。

Q5：前端登录报 Failed to fetch？

反代会在本地应答浏览器 CORS 预检（上游对不带 apikey 的 OPTIONS 回 401，浏览器要求预检必须 2xx）。2026-10-02 已修复上线；若再遇到，先确认 /healthz 能打开，再看 supabase-proxy 的 Logs 排查。

Q6：想改上游项目或加第二个 Supabase 项目？

改/复制 supabase-proxy/wrangler.toml 的 name、UPSTREAM_HOST、routes.pattern 三处，重新 npx wrangler deploy。
